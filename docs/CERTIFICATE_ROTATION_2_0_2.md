# 2.0.2 인증서 교체 대응

## 완료 기준과 시나리오
- 정상: 현재 서버의 새 R46 체인에서 정상 TLS와 핀 확인이 모두 통과한다.
- 오류: 이전 2.0.1 핀만 사용할 때 새 체인(구 Root R3 제외)은 거절된다.
- 오류: 무관한 자체 서명 인증서는 새 핀 검사에서도 거절된다.
- 기존 기능: 구 핀 세 개를 모두 유지하며 로그인·예약·쿠키·토큰 처리에는 손대지 않는다.

## 원인
서버의 leaf 인증서가 2026-11-02에 갱신됐다. Android가 받은 체인은 새 중간 인증서와
GlobalSign Root R46으로 끝나며, 앱의 기존 leaf/구 중간 인증서/구 Root R3 핀과 일치하지 않는다.
Windows는 교차 서명 체인에 구 Root R3를 더 붙이기도 하므로 Windows 연결 성공만으로
Android에서 구 핀이 유효하다고 판단할 수 없다.

## 변경
- 새 중간 인증서 SPKI: sha256/nZ4QsWxivBcuuFkI8dXgfa0Pb2o1sjZ8hKx6h+729xw=
- 기존 세 핀은 유지한다. 새로운 루트 전체나 임의 인증서를 허용하지 않는다.
- 인증서 핀을 KorailTlsPolicy로 분리해 같은 정책을 앱과 테스트에서 사용한다.
- 인증서 파일을 저장하지 않는다. 거절 검사는 JVM 기본 신뢰 저장소의 무관한 공개 인증서를 사용한다. 새/구 핀 비교는 명시적으로 활성화한 실제 TLS 연결에서만 한다.

## 실제 환경 확인
2026-11-14 KST에 .NET SslStream의 기본 검증(우회 콜백 없음)으로 호스트 이름·시스템 신뢰를 확인했다.
leaf: *.korail.com, 2026-11-02~2027-05-20.
중간: GlobalSign GCC R46 OV TLS CA 2025, 2025-09-17~2029-06-23.
최종 휴대폰의 로그인·조회·예약은 사용자 확인 대상이다. 과거 2.0.1 사용자 검증을 이번 결과로 대신하지 않는다.

## 사용자가 확인할 방법
업데이트 설치 후 설정→로그인 확인, 좌석 현황→다시 조회를 실행한다.
인증서 오류가 없어졌는지 확인하고 실제 사용할 열차 조건으로 예약을 확인한다.
실패하면 설정의 연결 진단 결과를 공유한다. 기존 앱은 삭제하지 않는다.

## 되돌리기
문제가 있으면 공개 버전 정보 JSON만 직전 내용으로 되돌려 추가 설치를 막는다.
이미 설치된 기기는 자동으로 내려가지 않으므로 수정 버전을 새로 게시한다.

## 사용자 결정 (2026-11-14)
- 인증서 파일 없는 테스트로 변경한다.
- 최종 APK의 휴대폰 확인을 게시 후 수행하는 예외를 이번 배포에 승인했다.
- 보안 hook을 건너뛰거나 인증서 파일 허용 범위를 넓히지 않는다.
