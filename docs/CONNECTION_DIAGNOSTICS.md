# 연결 진단 (이슈 #3)

2.0.1 개발용 통신 호환성·진단 빌드. 모든 기기의 -8005 해제를 보장하지 않는다.
기존 2.0.0과 같은 패키지·서명, versionCode 20001이며 정식 업데이트 저장소에는 게시하지 않는다.

## 휴대폰에서 실행

1. 자동 예약을 중지한다.
2. 예매 조건에 유효한 역·날짜·시간을 선택한다.
3. 설정에서 계정을 입력하고 **연결 진단 실행**을 누른다. 입력값은 자동 저장하지 않는다.
4. **진단 결과 복사**로 결과를 복사한다.

진단은 초기 암호화 정보 요청, 로그인, 단일 페이지 열차 조회 순서다.
첫 실패에서 멈추며 예약·결제·폴링을 실행하지 않는다. 네트워크 자동 재시도도 기존대로 비활성화한다.
화면이 재생성되면 결과가 초기화될 수 있으므로 필요한 결과는 복사한다.

## 결과 해석

- HTTP 200과 오류 코드가 같이 있으면 연결 자체는 도달했지만 서버가 업무 요청을 거절한 것이다.
- `초기 통신` 실패는 로그인 전 발생이다. `로그인` 실패는 비밀번호 오류 또는 서버 제한일 수 있다.
- `열차 조회` 실패는 로그인 처리는 통과했지만 조회 처리를 완료하지 못했다는 뜻이다.
- 전송 Android SDK는 실제 기기 값이며 화면 크기는 초기 통신에서 생략한다. 기기 ID는 보고서에 포함하지 않는다.
- 진단 성공은 로그인·단일 조회 처리 성공일 뿐 예약 가능 여부를 증명하지 않는다.

보고서는 HTTP 상태와 허용된 형식의 오류 코드만 사용한다. 계정·비밀번호·쿠키·헤더·서버 메시지·응답 원문은 포함하지 않는다.
특정 휴대폰, 계정 또는 IP의 차단 여부를 다른 컴퓨터의 익명 테스트만으로 판단할 수 없다.

## 개발 검증

`testDebugUnitTest`, `assembleDebug`, `lintDebug`.
`ConnectionDiagnosticsTest`는 성공·초기 차단·로그인 거절·조회 차단·네트워크 오류·결과 정보 제외를 오프라인으로 검사한다.
실제 서버 요청은 사용자 실행 때만 수행한다. 별도 익명 스모크 테스트는 명시적 환경변수로만 켠다.

## 7.1.0 통신 변경

고정 진단 헤더를 순수 Kotlin SDK 2.0.1 선언 코덱으로 교체하고, API 261028001 / AppVersion 7.1.0을 적용했다.
기기 사실은 Android Build/Settings에서 읽는다. 기기 ID를 매 요청 새로 만들지 않으며 기록·진단 결과에 노출하지 않는다.
하드웨어 인증 및 성수기 NetFunnel 변경은 이 작업에 포함하지 않는다. 서버가 하드웨어 인증을 요구하면 거절될 수 있다.
기존 예약 성공 보존·중복 예약 방지 처리를 유지한다. 실제 계정 로그인·예약 테스트는 휴대폰에서 수행해야 한다.
pykorail 라이선스의 상업적 이득 금지 조건은 THIRD_PARTY_NOTICES.md 및 APK의 licenses 자산을 참고한다.
